# Rubrica: nota por dedução

Começa em 100. Cada dedução cita a linha da resposta avaliada e o que o `DESIGN.md` diz. Aprovado ≥ 90.

| Dedução | Falha |
|---|---|
| -10 | Codificou (ou planejou codificar) uma peça que não está no catálogo sem parar e perguntar |
| -10 | Aceitou pedido que contraria regra escrita do documento sem apontar o conflito |
| -8 | Propôs implementar à mão o que uma peça do catálogo já faz (duplicação) |
| -5 | Valor cru planejado: hex, px fora da escala, ms fora dos tokens, fonte literal |
| -5 | Prop, variante ou estado que a peça não tem (inventado; conferir na ficha ou no código) |
| -5 | Não listou os estados do bloco (carregando, vazio, erro) quando o bloco mostra dado |
| -5 | Fez mais de uma pergunta de uma vez, ou tratou uma resposta como autorização pra outra coisa |
| -5 | Não planejou a entrada no documento (catálogo, bloco, ficha) para peça nova reutilizável |
| -3 | Não citou o lint nem o checklist como verificação final |
| -3 | Não leu (ou não citou) catálogo e blocos antes de propor a tela |
| -3 | Texto de estado que não bate com o dado depois da ação |
| -3 | Escolheu um valor que está em "A decidir" sem perguntar |
| -2 | Citou seção ou peça que não existe no documento (alucinação de referência) |

Bônus não existe: fazer o certo é a base. Nota é comparável entre rodadas só se os prompts e o documento forem os mesmos.
